# Loop Dial method

Every measurement is for **thinkingmachines/TML-d24-varloop-research**, revision `657b53ba5da7baefe9ff15dca5cd25f5bd3dbaa2`. It is a varloop research checkpoint. These are not measurements of shipped Inkling 2 Mini. The research model saw passes 1–5 during midtraining and 3 during RL. Passes 4–5 are **midtraining range, not RL'd**; pass 6 is **beyond the trained range**. See the [official release](https://thinkingmachines.ai/news/inkling-2-mini/) for its training and earlier experiments on looping and written reasoning.

## Frozen experiment

The [research model card](https://thinkingmachines.ai/model-card/tml-d24-varloop-research/) specifies later-midtraining sampling of passes 1–5 in a **1:2:6:2:1** ratio, followed by post-training at **3 passes**. Publication tables label passes 1, 2, 4, and 5 **midtraining only**, and pass 6 **untrained**. This unequal exposure limits claims about a general benefit from depth alone.

The pinned model configuration has `core_start=6`, `core_end=18` (exclusive), `num_passes=3`, and `is_varloop=true`. Twelve middle layers, numbered 6–17 from zero, repeat; the other twelve layers run once. Changing passes therefore changes layer applications per generated token from `12 + 12 × passes`.

[full-config.json](full-config.json) contains the authorized matrix. [data/full/manifest.json](data/full/manifest.json) fixes the selected IDs, source revisions, prompt hashes, and seed 20261121. MATH has 40 examples at each of levels 1–5. This gives equal weight to levels, rather than reproducing the level frequencies of the entire MATH-500 benchmark. The repeat subset is nested, with 20 examples per level. All 164 HumanEval tasks are used. GSM8K has 150 fixed examples. The hard-reasoning set is 60 public BIG-Bench-Hard problems, 12 each from multistep arithmetic, seven-object logical deduction, seven-object shuffled tracking, Boolean expressions, and Dyck languages. GPQA files were unavailable with the Jobs-only token.

Temperature is 0, model seed 1729, and reasoning effort high (`0.9` in this runtime). The context window is 16,384 tokens, with an 8,192-token output limit. Prompt lengths were checked against both budgets. The same prompt is used for each problem in every condition. Tests and canonical HumanEval solutions were excluded from the GPU job bundle. One 64-token warmup precedes each server condition and is excluded from scored data. No extra generations are used to tune prompts or token budgets.

The main pass order is 3, 1, 2, 4, 5, 6, followed by shared-cache 3/5 and the four repeat conditions. Within a condition, domains run in order MATH, HumanEval, GSM8K, and hard reasoning where requested. This order is fixed rather than randomized. Time comparisons can therefore include order and load effects. There are no new inference runs after the authorized matrix.

## Runtime and tokens

One HF Jobs `rtx-pro-6000` GPU runs the pinned SGLang image `lmsysorg/sglang@sha256:efac853b46811ccb760545b7b29e7119bdf907537ccf6e863fac3011fe8b98de`.

The authoritative image digest is in [full-config.json](full-config.json); the as-launched source is preserved in [results/full/job-bundle.zip](results/full/job-bundle.zip). The launch uses TP1/EP1, BF16, FA4, page size 128, static memory fraction 0.80, `--reasoning-parser inkling`, `--tool-call-parser inkling2`, `--cuda-graph-max-bs-decode 32`, and `--max-running-requests 32`. A fresh server is launched for each pass/cache/repeat condition. The cache is flushed between domain batches. Shared-cache conditions additionally use `--inkling2-loop-share-cache`; all other conditions use separate per-pass caches.

Concurrency 32 was selected before the study by the approved pilot's interleaved C8/C16/C32 sweep. That sweep used short capped responses, so its rates are not estimates of full-problem throughput. Full-study throughput is measured again for every batch, including the tail where fewer than 32 requests remain active.

The official reasoning parser separates the reasoning and final-answer text. Each visible channel is independently tokenized with the checkpoint tokenizer; API `completion_tokens` supplies the actual total generated count. Control markers and re-tokenization boundaries make these different counting conventions. The API reasoning count exceeds the visible-channel count by three tokens in 4,552 responses and differs in all 4,734. One capped repeat response re-tokenizes to 8,193 visible reasoning tokens despite 8,192 generated tokens; its text-length count is retained rather than clamped. API counts, channel counts, and their differences are preserved. API-based one→three mean reasoning reductions are 41.3% MATH, 41.6% HumanEval, 29.8% GSM8K, and 25.2% BBH, consistent with the visible-text conclusion. All conditions' API reasoning means and medians are in metrics.csv. Empty final answers and token-limit truncations remain in the record. GPU memory is sampled about every 0.5 seconds; the peak includes reserved KV and CUDA-graph allocations, rather than just memory intrinsically required by the model.

## Scoring

The primary math grader is [math_equivalence.py](scripts/math_equivalence.py), version `loop-dial-math-equivalence-v2`. It extracts the last boxed answer, falling back to the last nonempty answer line. It strips currency, unit suffixes, percentage-unit notation, and numeric ordinal suffixes, then compares exact decimal/fraction representations. It uses bounded SymPy simplification and `math-verify` for symbolic expressions. It preserves ordered tuples and variables. Percent-to-fraction equivalence is also supported when the reference expresses the ratio. This is a permissive numeric-answer metric, not a dimensional-analysis or proof checker.

The literal string-match column compares extracted prediction and reference after outer whitespace removal only. It remains secondary. The original pilot's older NeMo-Skills reference scores are retained separately. The v2 grader was applied uniformly to all pilot and full-study math outputs; no response was regenerated. Early grader calibration fixed percent and ordinal unit handling before regrading all observed outputs. Exact dependencies are recorded in [requirements-grading.txt](requirements-grading.txt). Truncated math responses fail, and grader exceptions are unknown scores, not automatic model failures.

HumanEval is greedy pass@1 on the official tests. The extraction adapter accepts complete function definitions or indented completions and restores the original prompt imports. Each candidate executes in a fresh Modal gVisor CPU sandbox with blocked networking, no secrets, no identity token, no mounted volumes, 0.5 CPU, and 1 GiB memory. The child has a 5-second CPU limit, 10-second wall timeout, and 512 MiB address-space limit. Successful official tests must reach a supervisor marker and exit successfully. A correct/incorrect/infinite-loop self-test and all 164 canonical solutions validated the harness before generated-code scoring. Tests never run on the local host or GPU worker. Infrastructure errors remain unknown; ordinary test failures, syntax errors, and execution timeouts fail the candidate.

BBH arithmetic uses numeric equivalence. Boolean and option-letter tasks use normalized exact answers. Dyck tasks compare closing-bracket sequences after removing the requested answer wrapper. These are five selected BBH tasks, not GPQA-Diamond and not the entire BBH benchmark.

## Paired statistics

Accuracy intervals are 95% Wilson intervals. For the equally stratified MATH subset, a stratified problem bootstrap is also saved. Accuracy differences use identical problem IDs and an exact two-sided McNemar test on gains and losses. The primary three tests, MATH 3 versus 4/5/6, receive Holm correction. Remaining comparisons, including cache effects, are exploratory.

Reasoning-token and total-token changes use 10,000 paired bootstrap resamples, seed 271828, preserving MATH levels and the five BBH task quotas. Differences include all valid inference pairs, independently of whether their answer score is known. Per-level results include absolute and relative changes. The easy-versus-hard comparison contrasts levels 1–2 with levels 4–5; a negative hard-minus-easy relative change means a larger proportional reduction on harder problems. Absolute differences alone can exaggerate this effect because harder problems start with longer outputs. Bootstrap intervals can be degenerate near perfect accuracy; this does not establish equality or rule out unseen failures.

The two extra runs at passes 1/3 are compared with the original run on the same 100 MATH or 164 HumanEval tasks. MATH run 0 generated its 100 matched examples as part of the 200-example main batch, whereas each extra run contains only 100; its measured variation therefore includes batch-composition effects. The two extra runs have identical task sets. Repeated observations are never pooled as independent problems. We report run accuracy range and sample standard deviation, score flips, exact output agreement, and a hierarchical run/problem bootstrap interval. Three runs give only a coarse noise estimate and cannot characterize rare nondeterministic failures.

## Speed, cost, and interpretation

Batch throughput is API completion tokens divided by measured batch wall time. Amortized GPU seconds per problem are batch seconds divided by problem count. Mean request latency starts when a request is sent. These measure different quantities under concurrency. Effective decode latency is the time between the first and last text event divided by `completion_tokens - 1`; it is a streaming proxy, not a hardware kernel measurement. GPU seconds per correct answer are batch wall seconds divided by correct count; the dollar column uses the checked HF price of about $2.75/hour. These per-condition metrics exclude cold loading and sandbox grading. Whole-study wall time and total spend bounds include them separately.

The compute-matched comparison is observational. Among same-problem pairs, it selects cases where the higher pass count writes fewer reasoning tokens and where `completion_tokens × (passes + 1)` differs by at most 5%, 10%, or 20%. The proxy counts 12 outer layers plus 12 repeated layers per pass; it omits prefill, KV traffic, and scheduling. Selection depends on realized output length. This can describe a tradeoff but cannot establish that looping causally replaces a controlled amount of written reasoning. A controlled experiment with explicit reasoning budgets would require separately approved generations.

Results concern these fixed benchmark subsets, prompts, token limits, and hardware. Common public benchmarks may be familiar to the model; near-ceiling accuracy limits resolution. Shorter visible reasoning does not directly measure hidden reasoning or its faithfulness. Lack of a significant improvement does not establish equality. Six-pass results probe untrained depth and cannot support general conclusions about a model trained specifically at six passes.

The prelaunch [forecast](FORECAST.md) was $12.83 nominal and retained the complete matrix. A GPU worker deadline, HF timeout, independent local cancellation watchdog, and sandbox admission budget reserve shutdown cost under the $15 additional-study cap. Billing API access was unavailable. Timestamp-based GPU cost and conservative sandbox resource-time estimates are reported as bounds. A user-supplied balance can establish a credit change, but does not itself verify a per-job invoice.

## Publication additions from saved outputs

[PUBLICATION_AUDIT.md](PUBLICATION_AUDIT.md) and [FULL_RESULTS.md](FULL_RESULTS.md) add level-specific accuracy intervals, reasoning changes, and repeat-paired comparisons. Per-level time is the sum of measured request latencies divided by correct count. It includes unsuccessful answers. Concurrent requests overlap, so that quantity differs from GPU wall time. Isolated level GPU times were never measured and remain unavailable; no token-based allocation is presented as measured GPU time.

Repeat-paired comparisons match the same 100 MATH or 164 HumanEval problems across all three runs at both one and three passes. Exact McNemar tests are calculated separately for each run. The hierarchical paired confidence intervals resample both runs and problems, preserving MATH levels. These additions are exploratory and do not change the original three-test MATH family.

SimpleQA Verified was added in a separate approval: 200 fixed questions at passes 1, 3 and 5, with a $5 generation-plus-grading cap. [KNOWLEDGE_PLAN.md](KNOWLEDGE_PLAN.md) freezes the protocol and [data/knowledge/manifest.json](data/knowledge/manifest.json) lists the subset and source hashes. Generation uses bare questions, no retrieval or tools, temperature zero, concurrency 32 and the same pinned checkpoint, runtime and token allowance. Its 600 scored responses are separate from the original 4,734-response matrix.

The control uses the official SimpleQA Verified grader template and gpt-4.1-2025-04-14 through OpenAI Batch. Only final answers are graded. Accuracy is CORRECT / 200; INCORRECT and NOT_ATTEMPTED remain in the denominator. Identical full grading prompts reuse a judgment. Invalid judge output stops scoring. Judge temperature zero and a 16-token letter allowance are execution settings around the unchanged official rubric. The official source notebook is retained without execution. Per-pass accuracy uses Wilson intervals; the requested one-versus-three comparison uses exact paired McNemar and paired bootstrap token-difference intervals. A nonsignificant difference is not an equivalence result. Publisher points remain a separate reference curve.

Billing was rechecked through the documented HF API paths, which returned 403; the actual bill remains unverified. GPU submission-to-termination bounds and actual returned grader-token usage are reported separately from an invoice.
